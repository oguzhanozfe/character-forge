# Instructions for AI agents (Codex, Claude, others)

You are operating **character-forge**, a gated pipeline that turns a brief or a reference image into a packaged game
character. The detailed procedure is the skill [.agents/skills/character-forge/SKILL.md](.agents/skills/character-forge/SKILL.md);
read it before your first command. This file is the short contract.

## Non-negotiables

1. **Drive the pipeline through `forge`**, not by editing run folders. Every stage run is hash-keyed; hand edits to
   `characters/<id>/stages/**` are detected as `modified` and must be redone through the tool.
2. **Stop at every gate that needs approval and ask the human**, showing what they need to look at (`forge show`, the
   preview/pose/contact-sheet PNGs, the WARN/FAIL checks). Approve with `--by human` only when the human said so in this
   conversation, quoting their decision in `--note`. Your own review is `--by agent`; it unblocks a stage only when the
   character was created with `--review-policy agent`. Never claim a human approved something they did not.
3. **Never waive a FAIL.** Fix the cause (inputs, landmarks, parameters, source) and rerun. Only a human may use
   `--waive-failures`.
4. **Never publish intermediates.** Do not commit or upload `.blend/.glb/.ply/.npz/.obj/.bvh`, renders, contact sheets,
   weights or logs. Only `forge package` output leaves the workspace, and it goes to the user's game project, not git.
5. **One GPU job at a time.** Real reconstruction and Kimodo take the machine-wide `gpu` lock automatically; do not start
   GPU work outside `forge`, never kill another process or delete a lock you do not own (`forge lock status` to see it).
6. **No downloads or installs without the human's explicit approval** (model weights, CUDA stacks, packages). Fake mode
   needs nothing. Read [LICENSE-NOTES.md](LICENSE-NOTES.md) before suggesting any backend; Hunyuan3D outputs are
   territory-restricted and the tool refuses it without an explicit `licence_ack`.
7. **Original fictional adults only** for references: no real-person likeness, celebrity, brand or franchise content.
   Record provenance for every reference (`--provenance`).
8. **Individuality matters more than speed.** Do not clone a previous character (scaled copies, recoloured duplicates,
   wearable-only variants). The preflight individuality gate compares silhouettes with the roster; similar is WARN, near
   identical is FAIL.
9. Report evidence and limits honestly: which modes were fake, which checks were WARN, what a human still has to look at.

## Commands you will use

```
forge new <id> --brief "..." [--reference img --provenance "..."] [--preset zombie|humanoid] [--mode fake|real]
forge run <id> [--until <stage>] [--stage <stage> --force]
forge status [<id>]
forge show <id> --stage <stage>
forge gate <id> [--render]
forge approve <id> --stage <stage> --by human|agent --note "what was inspected; what remains open"
forge reject  <id> --stage <stage> --by human|agent --note "why"
forge package <id>
forge lock status
forge clean <id>          # remove superseded runs (keeps current runs) - do this before you finish
```

Exit codes: `0` done, `1` a stage or gate failed, `2` usage/config error, `3` waiting for approval or input.

## Development on this repository

* Python 3.10+, stdlib only at runtime; `pip install -e ".[dev]"`; run `pytest` before committing. Tests must not need a
  GPU, Blender or downloads (Blender tests are skipped unless `FORGE_TEST_BLENDER` points at an executable).
* Fixtures are generated by the tests; never commit binary blobs over 1 MB.
* Keep Python as the single source of truth for poses, retargeting and gates; Blender scripts take explicit
  input/output paths and only write inside their output directory.
* Unity C# lives in `unity/com.characterforge.core`; it must compile against Unity 6000.3+ and carry EditMode tests.
